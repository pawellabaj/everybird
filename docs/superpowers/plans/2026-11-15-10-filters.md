# One Filters button (item 10) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the dock's Places, Time and Conservation status buttons with one "Filters · N" button that opens one panel (Time across the top, Places 2/3 and Conservation status 1/3 beside each other below it; a bottom sheet under 600px), and show the active place, time and status filters as removable chips under the dock.

**Architecture:**
- **Panel.** A new shell, `src/components/filters/Filters.tsx`, replaces `FilterDropdowns.tsx`.
  - `FiltersButton` sits in the dock's existing `filters` slot.
  - From 600px, `FiltersPanel` is a popover in a new `below` slot of `ControlsBar`, inside `.eb-dockwrap` after the chip row, so it anchors under the chips, or under the dock with none (spec 15).
  - While it is open, everything after the dock wrap in `CollageView` (the taxonomy row, the collage, the legend) sits in one `display: contents` wrapper that is `inert` and dimmed to 30%. A press there closes the panel.
  - Under 600px it is the modal bottom sheet, as today.
  - It mounts the existing `PlacesList`, `Timeline` and `StatusList` unchanged (spec 11); only their heads' strings change (spec 8).
- **Chips.** A pure model, `src/lib/list/chips.ts`, holds the `Chip` type item 9 will share, plus `filterChips` and `withoutFilterChip`. A presentational `ChipRow` (`src/components/filters/ChipRow.tsx`) renders them under the dock, in the same `below` slot.
- **Strings.** New strings live in `filter-summary.ts` (`FILTERS_UI`, `countHead`), so the i18n branch can lift them in one move.

**Tech Stack:** Next.js 16 app router (read `node_modules/next/dist/docs/` before touching anything Next-specific; nothing here is), React 19, TypeScript, plain CSS with container queries, Vitest + Testing Library (jsdom). The Playwright specs are neither written nor run here; the four that test the three drops are deleted, and the rest must still typecheck.

**Spec:** `.superpowers/sdd/2026-11-15-10-filters/spec.md` (git-ignored; its full text is in the Appendix below). Read `AGENTS.md` (the Next.js warning, Rules, Commands, and the Structure notes on ControlsBar, FilterDropdowns, Places, Timeline, StatusList, filter-summary, headroom, dialog-utils) and `DESIGN.md` ("Dock", "Chips and filters", "Places, Time and Conservation status dropdowns", "Layers", "Accessibility") first.

**Base.** Branch `feat/nf-10-filters`, cut from `feat/nf-3-iucn` once that is pushed. The base was still moving while this plan was written, so cite symbols, not line numbers. Before Task 1, check that the base includes `a27f5dd` (item 5 merged; `PlacesList` renders `PlacesDrill` only, no `PlacesTree`, no `places` preview variant) and that these exist: `FilterDropdowns.tsx` with `PANELS`, `PlacesDrill.tsx`, `StatusList.tsx`, `status-icon.ts` (`STATUS_ICON`), `placeCountsFor` in `places-shared.tsx`, and the `:where(.eb-dock:has(.eb-dock-drop:nth-child(3)))` rules in `app.css`. ## Builder's calls (decided here; the ones marked Q are also questions for Yusuf)

1. **N in "Filters · N"** counts the filter groups in use, 0 to 3 (spec 12). Implemented by `filtersCount(f)`: places set, time set, statuses set. It stays one digit, so the dock's width arithmetic doesn't change.
2. **Accessible name:**
   - With filters on, it is `Filters: ` plus each section in use, joined by `. `. For example: "Filters: Places: Kenya; British Columbia, Canada. Time: March 2020 to June 2021. Conservation status: Vulnerable". This uses the existing `placesSpoken`, `timeSpoken` and `statusSpoken`.
   - With none it is "Filters".
   - The visible "Filters · 3" starts with the name, which satisfies WCAG 2.5.3 (label in name).
3. **The button keeps the classes `eb-dock-tab eb-dock-drop` inside `.eb-dock-filters`.**
   - The existing two-drop rules (the 819px wrap, the 599px row at 36px, the under-300px grid, the under-240px row) then hold unchanged for the single button.
   - The three-drop `:where(…nth-child(3))` rules become a pure deletion.
   - On phones the button fills row two at full width, as today's drops do (Q5).
   - The 820px break is not retuned (Q5).
   - Glyph: the site's `FilterLinesIcon` (`collage/icons.tsx`), since DESIGN uses site glyphs in the dock. The caret is kept.
4. **Chips:**
   - Placement: one wrapped row inside `.eb-dockwrap`, right after `.eb-dock` (`ControlsBar`'s `below` slot), 12px under it, so it sits above `FilterBar`.
   - `ChipRow` is always mounted and returns null with no chips. `CollageView` never wraps it in a conditional, so `onEmpty` can fire after the last chip goes.
   - The open popover sits under the row (spec 15): the chips stay visible and undimmed, update live, and their × works while the panel is open.
   - Order: places (in `filterPlaceKeys` order), then time, then statuses (in `IUCN_CATS` order).
   - Look (Process change): `.eb-chip` (32px, 8px squircle, Surface fill), always in the active state: Accent border and Accent text. The × is a 20px square-ish press inside the chip's right end, holding a 14px `CloseIcon`. The chip itself keeps `.eb-chip`'s 44px-tall `::after`.
   - A single chip is one button; pressing it anywhere removes that one value. This is today's `Chip` removable form, named "Remove Canada filter", with the × drawn inside.
   - A collapsed chip ("5 places", "4 statuses") is two buttons: the label opens the panel and focuses that section; the 20px × clears every value of that kind.
5. **Chip labels:**
   - A place uses its short name (`placeName`), spoken with its parent (`placeNameLong`).
   - Time uses `timeSummary(f)` ("2022–2024", as spec 12 shows; "2022" within a year, "Sep 2021" for one month, "from 2022", "to 2024"), spoken in full months by `timeSpoken`.
   - A status uses its full name (`IUCN_NAMES`), the same in speech.
   - Collapsed chips read "N places" and "N statuses" (Q3).
6. **Section titles:**
   - Each section opens with a mono title and its glyph: Places (GlobeHemisphereWest), Time (CalendarBlank), Conservation status (`STATUS_ICON`, so Yusuf's Leaf stays) (Q7).
   - A section is a `role="group"` labelled by its title, `tabIndex={-1}`, `data-testid="filter-panel-<kind>"`. Keeping the old panel test ids on the sections makes the test migration mostly one-line swaps.
7. **Panel head:**
   - The head is `panelHead(n, shown)`: "Filters · 3 · 118 species", or "Filters · 118 species" at n = 0 (Q4).
   - `shown` is `CollageView`'s `shownList.length`, passed down, never recounted.
   - The head is `role="status"` (polite), so a checkbox's new total is read out.
   - In the sheet, the head replaces the sheet title. The footer is one `.eb-btn` "Show 118 species", which closes the sheet.
8. **The popover, the dim, scroll and height:**
   - The popover is today's `.eb-drop` (Paper, Hairline, the 16px squircle, the floating shadow) with `data-kind="filters"`: `left: 0; right: 0`, `max-height: 70vh`, a flex column. Its containing block is `.eb-dockwrap` (already `position: relative`), not `.eb-dock`, so `top: calc(100% + 6px)` puts it under the chip row, or under the dock with none.
   - The dim: `CollageView` wraps everything after `ControlsBar` except the bird card (`FilterBar`, `filterNote`, the stage or list, the legend) in `<div className="eb-view-below" inert={dimmed || undefined} data-dim={dimmed || undefined}>`, where `dimmed = filtersOpen && !sheet`.
     - `.eb-view-below { display: contents; }`, so the column's 12px gaps are unchanged.
     - `.eb-view-below[data-dim] > * { opacity: .3; transition: opacity .2s var(--eb-ease); }`, with no transition under reduced motion.
     - `inert` keeps a press on the dimmed area from reaching a bird or a chip there. The press falls through to the page, where the popover's document `pointerdown` handler closes the panel, as `DropPanel`'s does today.
     - The stats line and notice above the dock stay undimmed, as the dock and chips do.
     - Filters still apply live underneath: the collage re-packs dimmed.
   - Places' and Status's lists (`.eb-checklist`) scroll inside their columns, with `overscroll-behavior: contain`. Their heads, breadcrumb, note and search stay pinned. Each list keeps `min-height: 132px` (3 rows), so on a very short window the panel body scrolls as the fallback.

   - In the sheet, the body scrolls as one, with the sections stacked Time, Places, Status (Q8). The sheet renders no `.eb-fpanel-row` wrapper, and every row/column rule is scoped under `.eb-drop[data-kind="filters"]`, so nothing sits side by side at 390px. The sheet has its own scrim, so no dim.
9. **Focus and closing:**
   - Opened from the button, focus goes to the dialog, as today. Opened from a collapsed chip, focus goes to that section (in the sheet it is also scrolled into view).
   - The popover closes on Esc (`useEscapeCapture`), a second press of the button, or a press outside `.eb-dockwrap`, which in practice is the dimmed area. A press on the dock or the chips doesn't close it, so removing a chip keeps it open.
   - The sheet closes as today: Esc, the scrim, its ×, and "Show N species".
   - On close, focus returns to the opener if it is still connected, else to the Filters button.
   - Pressing a collapsed chip's label while the popover is open focuses its section.
   - The sheet traps Tab (`trapTab`). The popover doesn't, as today; with the content below inert, Tab past the panel goes to the footer.
   - After a chip is removed by its own press, focus moves to the chip now at that index, else to the previous one, else (`onEmpty`) to the Filters button.
   - When the chips change without a chip press (a box unchecked in the panel), `ChipRow` moves no focus and doesn't call `onEmpty`, so focus stays in the panel.
10. **Performance (11k species):**

### The shared Chip model (spec 6)

Item 9's parser on `feat/nf-9a-search-data` (`src/lib/search/smart.ts`) already declares:

```ts
type Chip = {
  kind: 'date' | 'place' | 'group' | 'order' | 'family' | 'status' | 'basis'
  label: string
  token: string
  start: number
  end: number
}
```

with `withoutChip(input, chip)` removing the chip's span from the query.

- **The base model.** This plan creates it in `src/lib/list/chips.ts` with exactly those kinds and `{kind, label, token}`, plus an optional `spoken`.
- **Item 9's change, when it builds its UI.**
  - It imports that type: `export type SearchChip = Chip & { start: number; end: number }`, and its `withoutChip` takes a `SearchChip`.
  - It renders its "Understood as" row with this plan's `ChipRow`, which accepts any `Chip` subtype.
  - Its chips have no collapsed form, so it passes no `onOpen`.
- **Two removal functions, one model.** Filter chips remove through `withoutFilterChip(f, chip)` (filter in, filter out); item 9's `withoutChip` works on query text. Both share the one model.

This plan doesn't edit item 9's branch.
